# 無料枠フォールバックの実測メモ

このアプリのVLM(画像キャプション/タグ付け用AI)接続は、1つの接続がダメだったときに
自動で次の接続を試す「フォールバック」機能を持っています。ここでは、実際にこの
フォールバックを使って動作検証した際に観測した、各サービスの生の挙動をまとめます。

検証は数十枚規模の実画像バッチで行ったもので、各社のサービス状況は日々変わるため、
ここに書いた数字はあくまで**検証時点の一例**として読んでください。

## Gemini(標準の無料枠)

- 「最大限に詳細」なキャプション設定では、1枚あたり正常時でも**40〜90秒程度**かかる
- まれに応答が遅すぎてタイムアウトになったり、一時的なサーバーエラーが返ることがある
  (この場合はアプリが自動で1回だけ再試行する)
- 画像の内容によっては、Gemini側の安全フィルターに引っかかり、その画像だけキャプション
  生成を拒否されることがある(これは再試行しても解消しない)
- 総じて「動くが速くはない」。待ち時間中は画面の表示が長く変わらないことがあるが、
  これは正常動作(フリーズではない)

## OpenRouterの無料モデル(`:free`)

- OpenRouterの無料モデルは、**世界中の全利用者で共有されている**枠を使っている
- 実測の10枚バッチでは、フォールバック先としてOpenRouterの無料モデルに回った画像の
  うち、複数枚が「レート制限中(しばらくして再試行するか、自分のAPIキーを登録してください)」
  というエラーで失敗した
- これはアプリ側の実装では解決できない、OpenRouter側の無料枠そのものの制約
- この傾向がそのまま続く場合、枚数の多いバッチほど「一定割合が失敗して手元に
  何も残らない」ことになりやすい

## NVIDIA NIM(無料枠)

- 目的のモデルがNVIDIA側で即座に使える状態にない場合、**エラーが返るまで約2分待たされる**
  ことがある(「反応が無くて2分待たされた末に失敗」という、体感上もっとも厳しいパターン)
- この挙動が確認できたため、現在は初期設定の接続順序からNVIDIAを外している

## Groq(無料枠)

- 標準プロファイル(Gemma系)では、Groqは実際には対応するモデルを提供していないことが
  判明した(以前のバージョンでは誤ってGroqを候補に含めていたが、修正済み)
- 一部のQwen系プロファイルではGroqも選択肢として残っているが、こちらは今回の検証では
  実際の成功/失敗を確認できていない
- Gemma系での実利用価値が低いため、現在は初期設定の接続順序からGroqを外している


## 実測: 1バッチでどれくらい出せたか

標準プロファイル(Gemma系、Gemini→OpenRouter無料モデルの順でフォールバック)を使い、
実画像11枚のバッチを実際のアプリ画面から2回実行した結果は以下の通りです。

| | 所要時間 | 成功 | 失敗 | 1枚あたり平均 |
|---|---|---|---|---|
| 1回目 | 810秒(約13.5分) | 7枚/11枚(64%) | 4枚 | 約74秒 |
| 2回目(Gemini側の待ち時間調整後) | 755秒(約12.6分) | 9枚/11枚(82%) | 2枚 | 約69秒 |

失敗した画像は、いずれもOpenRouter無料モデルのレート制限(1回のみGeminiの安全フィルター)
が原因で、リトライしても同じバッチ内では回復しませんでした。つまり**無料枠フォールバック
だけに頼ると、11枚程度の小規模バッチでも2〜4割が「何も出力されずに終わる」ことが実際に
起こり得ます**。100枚規模のバッチであれば、同じ割合で18〜36枚前後が失敗する計算になります。

## まとめ・実用上のおすすめ

無料枠だけを渡り歩くフォールバックは、「どれか1つでも動けば助かる」という**保険としては
機能する**ものの、**速度や成功率を保証するものではありません**。特にOpenRouterの無料枠は
利用者全体で共有されているため、混雑時にはまとまった枚数のバッチで一定割合が失敗する
ことがあります。

安定してタグ付けを行いたい場合は、よく使うサービス(Geminiなど)については**ご自身の
APIキーを登録して使うこと**を推奨します。自分専用の枠になるため、無料の共有枠に起因する
失敗を避けやすくなります。
